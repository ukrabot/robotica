¿Qué es el módulo RFID RC522 y cómo funciona?

El módulo RFID RC522 es un lector y grabador de tarjetas de proximidad basado en el chip MFRC522 de NXP, que opera en la banda de 13.56 MHz bajo el estándar ISO/IEC 14443A. Se comunica con el microcontrolador mediante protocolo SPI, lo que lo hace compatible con Arduino, ESP32, ESP8266, STM32 y Raspberry Pi.

Su funcionamiento se basa en el acoplamiento inductivo. La antena en espiral impresa en la placa genera un campo electromagnético de 13.56 MHz. Cuando una tarjeta o llavero RFID pasivo entra en ese campo, la bobina interna del tag capta energía por inducción y alimenta su propio microchip, que no necesita batería. Una vez energizado, el tag responde modulando la señal, y el RC522 demodula esa respuesta para extraer los datos.

A diferencia de los lectores que solo identifican, el RC522 puede leer y escribir. Esto significa que además de obtener el identificador único (UID) de cada tarjeta, puedes almacenar información en sus bloques de memoria: un saldo, un nombre, un nivel de permiso o un contador de usos.

¿Qué son los tags pasivos? La tarjeta y el llavero incluidos no tienen batería ni electrónica activa. Toman toda su energía del campo que emite el módulo, razón por la cual funcionan indefinidamente pero solo a corta distancia. Por eso el alcance es de unos 6 cm y no de varios metros.

El error que más módulos RC522 ha quemado: conectar VCC a 5V. El módulo se alimenta únicamente con 3.3V. En el Arduino UNO usa el pin marcado 3.3V, nunca el de 5V. Los pines de datos SPI sí toleran las señales de 5V del UNO, así que no necesitas conversor de nivel lógico para MOSI, SCK ni SS.

Ventaja con ESP32 y ESP8266: estas placas operan de forma nativa a 3.3V en todos sus pines, por lo que la compatibilidad con el RC522 es total y sin ninguna consideración extra de niveles lógicos.

Código de ejemplo: leer el UID de una tarjeta

Instala primero la librería MFRC522 desde el Arduino IDE (Programa → Incluir Librería → Administrar Bibliotecas → buscar "MFRC522"). Luego carga este sketch, que imprime por el monitor serie el identificador único de cualquier tarjeta que acerques:

#include <SPI.h>
#include <MFRC522.h>

#define SS_PIN  10   // SDA del RC522
#define RST_PIN 9    // RST del RC522

MFRC522 lector(SS_PIN, RST_PIN);

void setup() {
  Serial.begin(9600);
  SPI.begin();
  lector.PCD_Init();
  Serial.println("Acerca una tarjeta RFID al lector...");
}

void loop() {
  // ¿Hay una tarjeta nueva presente?
  if (!lector.PICC_IsNewCardPresent()) return;
  if (!lector.PICC_ReadCardSerial()) return;

  Serial.print("UID detectado: ");
  for (byte i = 0; i < lector.uid.size; i++) {
    if (lector.uid.uidByte[i] < 0x10) Serial.print("0");
    Serial.print(lector.uid.uidByte[i], HEX);
    if (i < lector.uid.size - 1) Serial.print(":");
  }
  Serial.println();

  lector.PICC_HaltA();       // Detiene la comunicación con el tag
  lector.PCD_StopCrypto1();  // Cierra el cifrado
}

Abre el monitor serie a 9600 baudios y acerca la tarjeta. Verás algo como UID detectado: A3:F2:1B:7C. Ese UID es la huella digital de cada tag y es el dato que usarás para validar accesos.

Validar un UID autorizado

Para un control de acceso real, compara el UID leído contra una lista de tags permitidos. La forma más simple es concatenar los bytes en un texto y compararlo:

String uidTexto = "";
for (byte i = 0; i < lector.uid.size; i++) {
  if (lector.uid.uidByte[i] < 0x10) uidTexto += "0";
  uidTexto += String(lector.uid.uidByte[i], HEX);
}
uidTexto.toUpperCase();

if (uidTexto == "A3F21B7C") {
  Serial.println("Acceso autorizado");
  // Aquí activas el servo, relé o cerradura
} else {
  Serial.println("Acceso denegado");
}

Consejo: ejecuta primero el sketch de lectura para anotar el UID real de tu tarjeta y de tu llavero, y recién después reemplaza el valor en la comparación. Cada tag tiene un UID distinto de fábrica.

Estructura de memoria de las tarjetas MIFARE Classic

Las tarjetas incluidas suelen ser MIFARE Classic 1K, con 1024 bytes de memoria organizados de forma muy específica. Entender esta estructura es lo que separa leer un UID de realmente escribir datos en la tarjeta:

ElementoCantidadFunción
Sectores16 (0 a 15)División principal de la memoria
Bloques por sector43 de datos + 1 de control (trailer)
Bytes por bloque16Unidad mínima de lectura/escritura
Bloque 0 del sector 01Contiene el UID; es de solo lectura
Sector trailer16 (uno por sector)Guarda las claves A y B y los bits de acceso
Bloques de datos usables47Total disponible para tu información

Cada sector está protegido por dos claves de 6 bytes. De fábrica, ambas suelen venir en FF FF FF FF FF FF, que es la clave por defecto que usan los ejemplos de la librería MFRC522.

Precaución al escribir: nunca escribas en el bloque trailer de un sector sin entender qué estás haciendo. Si modificas las claves o los bits de acceso con valores incorrectos, el sector queda bloqueado de forma permanente e irrecuperable. Practica siempre en bloques de datos (por ejemplo el bloque 4) y nunca en el bloque 0, 3, 7, 11, etc.

Proyectos que puedes construir con el RC522

Nivel inicial

  • Lector de UID por monitor serie: el primer paso obligatorio, con el código de arriba.
  • Semáforo de acceso: LED verde si el UID está autorizado, rojo si no. Buen ejercicio de lógica.
  • Timbre identificador: el zumbador emite un tono distinto según quién pase su llavero.

Nivel intermedio

  • Cerradura electrónica con servo: el servomotor gira el pestillo al validar la tarjeta. Ver tutorial de servos.
  • Control de acceso con relé: activa una chapa eléctrica o electroimán. Ver módulo relé.
  • Panel con LCD: muestra el nombre del usuario y el estado del acceso en una pantalla. Ver LCD 16×2 con I2C.
  • Doble factor con teclado: exige tarjeta más clave numérica para abrir.

Nivel avanzado

  • Registro de asistencia con marca horaria: RC522 + módulo RTC guardando quién entró y a qué hora, con exportación a tarjeta SD.
  • Sistema de inventario: cada herramienta o insumo lleva un tag; el sistema registra retiros y devoluciones.
  • Monedero de prepago: escribe y descuenta saldo directamente en la memoria de la tarjeta, sin base de datos externa.
  • Control de acceso IoT: con ESP32, valida contra un servidor remoto y notifica cada acceso por WiFi.
  • Arranque de vehículo o maquinaria: habilita el encendido solo con el llavero autorizado presente.

El RC522 no lee: 7 causas frecuentes

Si el módulo no detecta ninguna tarjeta, casi siempre es una de estas razones, ordenadas por frecuencia real:

  1. Alimentación en 5V. Si lo conectaste a 5V, probablemente ya esté dañado. Verifica que VCC esté en el pin de 3.3V. Este es, por lejos, el problema número uno.
  2. Pines sin soldar correctamente. Los headers vienen sueltos. Una soldadura fría (opaca, con forma de bolita) no hace contacto eléctrico aunque se vea puesta. Reflúyela con más calor.
  3. Pines SPI equivocados. En Arduino Mega el bus SPI está en 50-53, no en 11-13. Revisa la tabla de pinout según tu placa.
  4. Librería mal seleccionada. Existen varias librerías llamadas parecido. Usa la MFRC522 de miguelbalboa, que es la estándar de facto.
  5. Cables demasiado largos. El SPI a 13.56 MHz es sensible: cables de más de 20 cm o mal contactados en protoboard generan lecturas intermitentes. Usa cables cortos.
  6. Metal cerca de la antena. Una superficie metálica detrás del módulo o de la tarjeta absorbe el campo y reduce drásticamente el alcance. Separa el módulo de cajas metálicas.
  7. Tarjeta de frecuencia incorrecta. Los tags de 125 kHz (típicos de llaveros antiguos de edificios) son físicamente incompatibles: el RC522 solo trabaja a 13.56 MHz.

Diagnóstico rápido: la librería MFRC522 incluye el ejemplo DumpInfo, que al iniciar imprime la versión del firmware del chip. Si muestra 0x00 o 0xFF, el módulo no está respondiendo: el problema es de alimentación, soldadura o cableado, no de tu código.

Límites de seguridad que conviene conocer

Si vas a usar el RC522 en un proyecto real de control de acceso, hay tres cosas que es honesto saber de antemano:

El UID no es un secreto

El identificador único se transmite sin cifrar antes de cualquier autenticación. Un sistema que valida solo por UID es cómodo para proyectos educativos y de conveniencia, pero no constituye seguridad fuerte, ya que existen tags programables capaces de replicar un UID ajeno.

MIFARE Classic tiene vulnerabilidades documentadas

El algoritmo Crypto-1 que protege los sectores fue criptoanalizado públicamente hace años. Para aplicaciones donde la seguridad sea crítica, la industria usa tarjetas MIFARE DESFire o similares, con cifrado AES.

Qué hacer entonces

  • Para proyectos educativos, prototipos, control de inventario o comodidad doméstica, el RC522 es perfectamente adecuado y es exactamente para lo que se usa.
  • Para accesos sensibles, combínalo con un segundo factor: clave en teclado, horario permitido o confirmación remota.
  • Registra siempre los accesos con marca de tiempo: la trazabilidad compensa buena parte de la debilidad del identificador.

¿A qué voltaje se conecta el RC522?

Exclusivamente a 3.3V. Conectarlo a 5V puede dañarlo de forma permanente. En un Arduino UNO usa el pin de 3.3V para VCC; los pines de datos SPI sí toleran las señales de 5V del microcontrolador sin conversor de nivel.

¿Cómo lo conecto a un Arduino UNO?

SDA al pin 10, SCK al 13, MOSI al 11, MISO al 12, RST al 9, GND a GND y VCC a 3.3V. El pin IRQ normalmente se deja sin conectar. Para otras placas revisa la tabla de pinout de esta página.

¿Qué librería debo usar?

La librería MFRC522, disponible gratis desde el gestor de bibliotecas del Arduino IDE. Trae ejemplos listos para leer el UID (DumpInfo) y para leer o escribir bloques de memoria.

¿Funciona con ESP32 y ESP8266?

Sí, y de hecho la compatibilidad es aún mejor: ambas placas operan de forma nativa a 3.3V, por lo que no hay que considerar adaptación de niveles lógicos en ningún pin.

¿Cuál es la distancia de lectura?

Hasta unos 60 mm, dependiendo del tipo de tag, del tamaño de su antena y del entorno. Las tarjetas planas se leen a mayor distancia que los llaveros, y el metal cercano reduce el alcance significativamente.

¿Puede leer mi tarjeta del transporte o de la oficina?

Puede detectar cualquier tarjeta de 13.56 MHz compatible con ISO 14443A y leer su UID. Sin embargo, los sectores de datos de tarjetas oficiales están cifrados con claves propias del emisor, por lo que no es posible leer ni modificar su contenido protegido.

¿Los pines vienen soldados?

No. El módulo incluye dos tiras de pines (recta y acodada) sueltas, para que elijas la orientación según tu montaje. Necesitarás un cautín; son 8 pines y es una soldadura sencilla.
