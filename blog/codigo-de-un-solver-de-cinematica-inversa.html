Fundamentos de los solvers numéricos basados en el Jacobiano

Cuando un manipulador robótico no admite solución analítica cerrada (como robots de 7 grados de libertad, robots con articulaciones prismáticas intermedias o cadenas con offsets complejos), se recurre a métodos numéricos iterativos. Estos algoritmos resuelven la cinemática inversa formulando un problema de optimización no lineal que busca minimizar el vector de error de pose:

$$\mathbf{e} = \begin{bmatrix} \mathbf{e}_{pos} \\ \mathbf{e}_{rot} \end{bmatrix} = \begin{bmatrix} \mathbf{p}_{target} - \mathbf{p}(\mathbf{q}) \\ \frac{1}{2} \left( \mathbf{n} \times \mathbf{n}^* + \mathbf{s} \times \mathbf{s}^* + \mathbf{a} \times \mathbf{a}^* \right) \end{bmatrix}$$

La relación diferencial entre las velocidades articulares $\mathbf{\dot{q}}$ y la velocidad espacial del extremo $\mathbf{v} = [\mathbf{\dot{p}}, \boldsymbol{\omega}]^T$ está gobernada por la Matriz Jacobiana Geométrica $J(\mathbf{q}) \in \mathbb{R}^{6 \times N}$:

$$\mathbf{\dot{x}} = J(\mathbf{q}) \cdot \mathbf{\dot{q}}$$

Inversión robusta: Damped Least Squares (Levenberg-Marquardt)

La inversión ingenua usando la pseudoinversa de Moore-Penrose ($J^+ = J^T (J J^T)^{-1}$) tiene una falla mortal: en las proximidades de una singularidad, el determinante de $J J^T$ tiende a cero, haciendo que los valores calculados de $\Delta \mathbf{q}$ tiendan a infinito.

El método de Mínimos Cuadrados Amortiguados (Damped Least Squares - DLS) resuelve esto introduciendo un factor de amortiguamiento $\lambda > 0$ que equilibra la precisión del seguimiento con la estabilidad numérica:

$$J^* = J^T \cdot \left( J \cdot J^T + \lambda^2 \cdot I_{6\times 6} \right)^{-1}$$

Donde el factor $\lambda$ se adapta dinámicamente según el índice de manipulabilidad de Yoshikawa ($w = \sqrt{\det(J J^T)}$): cuando el robot está lejos de singularidades, $\lambda \approx 0$ (máxima precisión); cerca de una singularidad, $\lambda$ aumenta para restringir las velocidades articulares.

Implementación completa en Python con NumPy

A continuación se presenta el código completo de un solver cinemático robusto para un brazo articulado:

import numpy as np

class InverseKinematicsSolverDLS:
    def __init__(self, link_lengths, joint_limits_min, joint_limits_max):
        self.L = link_lengths  # [L1, L2, L3, L4]
        self.q_min = np.array(joint_limits_min)
        self.q_max = np.array(joint_limits_max)
        self.num_joints = len(link_lengths)

    def forward_kinematics(self, q):
        """Cinemática directa simplificada para manipulador planar/espacial."""
        # Calcula posiciones de cada articulación y pose final
        x = self.L[0] * np.cos(q[0]) + self.L[1] * np.cos(q[0] + q[1]) + self.L[2] * np.cos(q[0] + q[1] + q[2])
        y = self.L[0] * np.sin(q[0]) + self.L[1] * np.sin(q[0] + q[1]) + self.L[2] * np.sin(q[0] + q[1] + q[2])
        theta = q[0] + q[1] + q[2]
        return np.array([x, y, theta])

    def compute_jacobian(self, q):
        """Cálculo analítico de la matriz Jacobiana 3x3."""
        J = np.zeros((3, 3))
        # Derivadas parciales dx/dq
        J[0, 0] = -self.L[0]*np.sin(q[0]) - self.L[1]*np.sin(q[0]+q[1]) - self.L[2]*np.sin(q[0]+q[1]+q[2])
        J[0, 1] = -self.L[1]*np.sin(q[0]+q[1]) - self.L[2]*np.sin(q[0]+q[1]+q[2])
        J[0, 2] = -self.L[2]*np.sin(q[0]+q[1]+q[2])

        # Derivadas parciales dy/dq
        J[1, 0] = self.L[0]*np.cos(q[0]) + self.L[1]*np.cos(q[0]+q[1]) + self.L[2]*np.cos(q[0]+q[1]+q[2])
        J[1, 1] = self.L[1]*np.cos(q[0]+q[1]) + self.L[2]*np.cos(q[0]+q[1]+q[2])
        J[1, 2] = self.L[2]*np.cos(q[0]+q[1]+q[2])

        # Derivadas de orientación d(theta)/dq
        J[2, 0] = 1.0
        J[2, 1] = 1.0
        J[2, 2] = 1.0
        return J

    def solve(self, target_pose, q_init, max_iter=100, tol=1e-4, lambda_damp=0.05):
        """Solver DLS con control de espacio nulo y límites articulares."""
        q = np.copy(q_init).astype(float)
        
        for iteration in range(max_iter):
            current_pose = self.forward_kinematics(q)
            error = target_pose - current_pose
            
            # Comprobar convergencia
            if np.linalg.norm(error[:2]) < tol and abs(error[2]) < tol:
                return q, True, iteration

            J = self.compute_jacobian(q)
            
            # Inversión Damped Least Squares (DLS)
            # J_dls = J^T * (J * J^T + lambda^2 * I)^(-1)
            JJT = np.dot(J, J.T)
            damped_inv = np.linalg.inv(JJT + (lambda_damp ** 2) * np.eye(3))
            J_dls = np.dot(J.T, damped_inv)
            
            # Actualización principal
            delta_q = np.dot(J_dls, error)
            
            # Optimización de Espacio Nulo para centrar articulaciones lejos de límites
            q_center = (self.q_min + self.q_max) / 2.0
            null_proj = np.eye(3) - np.dot(J_dls, J)
            q_null = 0.1 * (q_center - q)
            delta_q += np.dot(null_proj, q_null)
            
            # Clamping de paso máximo para estabilidad
            max_step = 0.2  # rad
            delta_q = np.clip(delta_q, -max_step, max_step)
            
            # Actualización y recorte por límites físicos
            q += delta_q
            q = np.clip(q, self.q_min, self.q_max)
            
        return q, False, max_iter

# Ejemplo de uso:
if __name__ == "__main__":
    solver = InverseKinematicsSolverDLS(
        link_lengths=[0.3, 0.25, 0.15],
        joint_limits_min=[-np.pi, -np.pi/2, -np.pi],
        joint_limits_max=[np.pi, np.pi/2, np.pi]
    )
    objetivo = np.array([0.45, 0.20, np.pi/4])
    q_inicial = np.array([0.1, 0.1, 0.1])
    
    q_solucion, exito, iteraciones = solver.solve(objetivo, q_inicial)
    print(f"¿Convergencia exitosa?: {exito} en {iteraciones} iteraciones")
    print(f"Ángulos articulares calculados: {np.degrees(q_solucion).round(2)} grados")

Optimización para bucles de control en tiempo real (1 kHz)

Para ejecutar este algoritmo en C++ dentro de un ciclo de 1 kHz (1 milisegundo por iteración):

  • Evitar alocaciones dinámicas de memoria (Heap Allocations): Usa tipos de matriz de tamaño fijo de la biblioteca Eigen (Eigen::Matrix<double, 6, 6>) para garantizar que los cálculos se realicen en la pila (Stack).
  • Descomposición Cholesky / LDLT: En lugar de calcular np.linalg.inv(), resuelve el sistema lineal $(J J^T + \lambda^2 I) \mathbf{y} = \mathbf{e}$ mediante descomposición Cholesky, que es 3 veces más rápida y numéricamente más estable.

Preguntas Frecuentes

¿Por qué el solver numérico a veces no converge aunque el punto sea alcanzable?

Ocurre típicamente si la pose inicial $q_0$ está cerca de una singularidad severa, si el factor de amortiguamiento $\lambda$ es excesivo (haciendo el avance extremadamente lento) o si los límites articulares recortan el vector de actualización antes de que pueda doblar la articulación en la dirección correcta. Probar con múltiples semillas iniciales aleatorias (Random Restarts) resuelve este problema.

¿Qué es la proyección en el espacio nulo (Nullspace Projection)?

En robots con redundancia cinemática (más de 6 GDL, o tareas donde no se controla la orientación completa), existen infinitas combinaciones articulares que mantienen el efector quieto. El operador de proyección $(I - J^+ J)$ permite utilizar esos grados de libertad libres para tareas secundarias, como alejarse de límites articulares o evitar colisiones.

¿Cuántas iteraciones suele tardar un solver DLS en converger?

Si el robot se está moviendo de forma continua a lo largo de una trayectoria suave (donde la pose anterior sirve como semilla $q_0$), el solver suele converger en 1 a 3 iteraciones (< 0.05 ms).

¿Cuál es la diferencia entre el Jacobiano Geométrico y el Analítico?

El Jacobiano geométrico relaciona velocidades articulares con velocidades angulares físicas $\boldsymbol{\omega}$. El Jacobiano analítico relaciona velocidades articulares con las derivadas temporales de los ángulos de orientación elegidos (como ángulos de Euler $\mathbf{\dot{\phi}}$). El geométrico es numéricamente preferible porque carece de las singularidades de representación de los ángulos de Euler.

¿Cómo se integra este código con MoveIt 2?

MoveIt 2 utiliza plugins de cinemática (`kinematics_interface`). Puedes compilar este código dentro de un plugin C++ basado en `kinematics_interface::KinematicsBase` y configurarlo en el archivo `kinematics.yaml` de tu robot.
