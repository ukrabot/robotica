Domótica con ESP32 y MQTT: Controla tu Casa desde el Celular

Qué es MQTT y por qué domina la domótica

MQTT (Message Queuing Telemetry Transport) es un protocolo de mensajería ligero creado para conectar dispositivos con pocos recursos, exactamente el escenario del Internet de las Cosas. A diferencia de otros protocolos más pesados, MQTT consume muy poco ancho de banda, funciona bien en redes inestables y permite que miles de dispositivos se comuniquen a través de un solo servidor.

  • Ligero: los mensajes son pequeños y el ESP32 puede manejarlos sin esfuerzo.
  • Desacoplado: los dispositivos no se conocen entre sí; solo hablan con el broker, lo que simplifica agregar o quitar nodos.
  • Ubicuo: hay librerías y aplicaciones para prácticamente cualquier plataforma, lo que lo hace ideal para domótica casera.
  • Bidireccional: un mismo dispositivo puede enviar lecturas y recibir órdenes por el mismo canal.

Broker, publicador y suscriptor

MQTT usa un modelo de publicación y suscripción con tres protagonistas:

  • Broker: el servidor central que recibe todos los mensajes y los redistribuye. Es el único punto de contacto común; sin él, los dispositivos no se encuentran.
  • Publicador: el dispositivo que envía un mensaje a un tema. Por ejemplo, un sensor que publica la temperatura.
  • Suscriptor: el dispositivo que declara interés en un tema y recibe automáticamente sus mensajes. Por ejemplo, la app del celular que muestra la temperatura.

Un mismo dispositivo puede ser publicador y suscriptor a la vez: el ESP32 publica el estado de un sensor y se suscribe al tema donde recibe las órdenes de encendido.

Temas (topics) y comodines

Los mensajes se organizan en temas, direcciones jerárquicas separadas por barras. Diseñar bien esta jerarquía desde el inicio es una de las decisiones más importantes del proyecto:

casa/sala/luz        -> estado de la luz de la sala
casa/dormitorio/luz  -> estado de la luz del dormitorio
casa/sensor/temp     -> temperatura del sensor interior

Los suscriptores pueden usar comodines para recibir varios temas a la vez:

  • + sustituye un solo nivel: casa/+/luz recibe las luces de todas las habitaciones.
  • # sustituye varios niveles: casa/# recibe todos los mensajes de la casa.

Configurar un broker MQTT

Para empezar sin instalar nada, puedes usar un broker público gratuito como test.mosquitto.org o broker.hivemq.com. Para un proyecto serio y privado, monta tu propio broker con Mosquitto:

  1. Instala Mosquitto en una Raspberry Pi o computador que esté siempre encendido.
  2. Configura el puerto (1883 por defecto) y, para uso doméstico, agrega autenticación con usuario y contraseña.
  3. Verifica que el broker sea accesible desde tu red local.
Regla práctica: broker público para probar, broker propio para quedarse. Los brokers públicos son compartidos y cualquiera puede leer tus temas; para una instalación real en tu casa, la privacidad y el control del broker propio lo justifican.

Conectar el relé para controlar luces

El ESP32 no puede manejar directamente la corriente de una lámpara o un enchufe: el relé actúa de intermediario, usando una señal débil del microcontrolador para abrir o cerrar un circuito de mayor potencia.

Módulo de relé           ESP32
--------------           -----
VCC                -->   5V (o VIN según el módulo)
GND                -->   GND
IN (entrada)       -->   GPIO 26

El pin IN recibe la señal de control: en HIGH el relé conmuta (enciende), en LOW se libera (apaga), dependiendo de si el módulo es activo alto o activo bajo. Verifica la lógica de tu módulo con una prueba simple antes de programar todo el sistema.

Código ESP32 con PubSubClient

La librería PubSubClient es la forma estándar de usar MQTT en ESP32. Instálala desde el gestor de librerías del IDE de Arduino y usa este esqueleto, que conecta el WiFi, se suscribe al tema de la luz y enciende o apaga el relé según el mensaje recibido:

#include <WiFi.h>
#include <PubSubClient.h>

const char* SSID     = "tu_red_wifi";
const char* PASS     = "tu_clave_wifi";
const char* BROKER   = "test.mosquitto.org";
const int   PUERTO   = 1883;

const char* TOPIC_LUZ = "casa/sala/luz";
const int   PIN_RELE  = 26;

WiFiClient clienteWiFi;
PubSubClient mqtt(clienteWiFi);

void conectarMQTT() {
  while (!mqtt.connected()) {
    if (mqtt.connect("esp32-sala")) {          // id unico del dispositivo
      mqtt.subscribe(TOPIC_LUZ);               // se suscribe al tema
    } else {
      delay(2000);
    }
  }
}

// Se ejecuta cuando llega un mensaje al tema suscrito
void callback(char* topic, byte* payload, unsigned int length) {
  String mensaje = "";
  for (unsigned int i = 0; i < length; i++) {
    mensaje += (char)payload[i];
  }

  if (String(topic) == TOPIC_LUZ) {
    if (mensaje == "ON") {
      digitalWrite(PIN_RELE, HIGH);
    } else if (mensaje == "OFF") {
      digitalWrite(PIN_RELE, LOW);
    }
  }
}

void setup() {
  pinMode(PIN_RELE, OUTPUT);
  digitalWrite(PIN_RELE, LOW);

  WiFi.begin(SSID, PASS);
  while (WiFi.status() != WL_CONNECTED) delay(500);

  mqtt.setServer(BROKER, PUERTO);
  mqtt.setCallback(callback);
}

void loop() {
  if (!mqtt.connected()) conectarMQTT();
  mqtt.loop();   // procesa mensajes entrantes y mantiene la conexion
}

La función callback es el corazón del sistema: cada vez que llega un mensaje, decide qué acción tomar según el tema y el contenido. A partir de aquí puedes agregar tantos temas como dispositivos tengas, repitiendo el mismo patrón.

Control desde el celular

No necesitas programar una app desde cero. Instala una aplicación MQTT gratuita en tu celular (como MQTT Dash o IoT MQTT Panel), conéctala al mismo broker y crea botones:

  • Un botón "ENCENDER" que publica ON en casa/sala/luz.
  • Un botón "APAGAR" que publica OFF en el mismo tema.
  • Opcionalmente, un indicador suscrito al tema que muestre el estado actual.

Cuando presionas el botón, la app publica el mensaje, el broker lo reenvía y el ESP32, suscrito al tema, lo recibe y actúa. Es la magia del modelo publicador/suscriptor funcionando en tiempo real.

Seguridad y alto voltaje

El alto voltaje no perdona errores: si vas a controlar cargas de 220V, usa módulos de relé con aislamiento y carcasa, nunca toques los terminales de alta tensión con el circuito energizado, y ante cualquier duda recurre a un electricista calificado. Para aprender, empieza con una carga de bajo voltaje (12V) o un LED.

Además del voltaje, considera la seguridad de la red: no expongas tu broker a internet sin autenticación y, si controlas dispositivos de forma remota, usa contraseñas robustas y una VPN en lugar de abrir puertos directamente.

Conclusión

Con un ESP32, un relé y MQTT tienes la base de un sistema de domótica completo: entiendes el protocolo, montas el broker, conectas el hardware y controlas todo desde el celular. Este es el punto de partida para proyectos mayores como el monitoreo remoto con Blynk o el registro y graficado de datos con ThingSpeak, que comparten la misma infraestructura de red que acabas de dominar.

Preguntas frecuentes

¿Qué es MQTT y por qué se usa en domótica?

MQTT (Message Queuing Telemetry Transport) es un protocolo de mensajería ligero diseñado para dispositivos con pocos recursos, ideal para el Internet de las Cosas. Funciona con un modelo de publicación y suscripción: los dispositivos no se hablan directamente entre sí, sino que publican mensajes en "temas" y se suscriben a los temas que les interesan, coordinados por un servidor central llamado broker. Su bajo consumo de ancho de banda, su capacidad para funcionar en redes inestables y su soporte universal lo convierten en el estándar de facto de la domótica y de proyectos con ESP32.

¿Qué es un broker MQTT y cuál debo usar?

El broker es el servidor que recibe todos los mensajes MQTT y los redistribuye a los suscriptores correspondientes. Para empezar, la opción más simple es un broker público gratuito como test.mosquitto.org o broker.hivemq.com, que no requieren instalar nada; para un proyecto serio conviene montar un broker propio con Mosquitto en una Raspberry Pi o computador local, o contratar un broker en la nube. La ventaja del broker propio es el control total, la privacidad y la posibilidad de agregar autenticación con usuario y contraseña.

¿Qué es un tema (topic) en MQTT?

Un tema o topic es la dirección lógica donde se publica un mensaje, estructurada por niveles separados por barras, por ejemplo "casa/sala/luz". Los suscriptores pueden usar comodines: el signo más (+) sustituye un nivel y la almohadilla (#) sustituye varios niveles, de modo que una suscripción a "casa/#" recibe todos los mensajes de la casa. Diseñar bien la jerarquía de temas desde el inicio evita conflictos cuando el sistema crece, y es una de las decisiones más importantes de un proyecto de domótica.

¿Puedo controlar 220V de forma segura con un ESP32 y un relé?

Un relé permite que el ESP32 controle cargas de 220V, pero trabajar con tensión de red es peligroso y debe hacerse con extrema precaución: usa siempre módulos de relé con aislamiento y carcasa protectora, nunca toques los terminales de alta tensión con el circuito energizado, y ante la duda prefiere un electricista calificado. Para aprender, la recomendación es empezar controlando una lámpara de bajo voltaje (12V) o un LED, y solo pasar a 220V cuando domines el cableado y uses protecciones adecuadas. La seguridad con alto voltaje no es opcional.

¿Necesito una app específica para controlar los dispositivos?

No necesitas programar una app desde cero. Existen aplicaciones MQTT gratuitas para iOS y Android (como MQTT Dash, IoT MQTT Panel o MyMQTT) que se conectan al mismo broker y te permiten crear botones e indicadores en pantalla que publican y se suscriben a tus temas. Configuras un botón para publicar "ON" en el tema de una luz y el ESP32, suscrito a ese tema, la enciende. Es la forma más rápida de tener control desde el celular sin desarrollar software móvil propio.
