Modelos de Lenguaje Locales con Ollama

La revolución de los modelos locales y la soberanía de datos

Depender exclusivamente de APIs comerciales en la nube (como OpenAI ChatGPT o Anthropic Claude) presenta tres problemas críticos para ingenieros, empresas y desarrolladores:

  1. Privacidad y Confidencialidad: Enviar código fuente propietario, esquemas de circuitos o registros médicos a servidores de terceros viola normativas de protección de datos (como GDPR o normativas industriales internas).
  2. Costo recurrente acumulativo: Facturas mensuales impredecibles basadas en consumo de tokens por millón en aplicaciones de análisis continuo.
  3. Latencia y dependencia de Internet: Si la conexión a la red falla, los sistemas robóticos o de automatización local quedan completamente inoperativos.

Ollama es un entorno de ejecución de código abierto que encapsula el motor en C++ llama.cpp en un servicio en segundo plano sumamente sencillo, permitiendo descargar y ejecutar modelos con miles de millones de parámetros con una sola línea de comandos y con cero telemetría exterior.

Física de la cuantización GGUF: 4-bit, 5-bit y 8-bit

Los modelos de lenguaje se entrenan originalmente en precisión flotante de 16 bits (FP16 o BF16). En este formato, un modelo de 8.000 millones de parámetros (8B) ocupa aproximadamente 16 GB de memoria de video, quedando fuera del alcance de la mayoría de computadoras de escritorio.

La cuantización en formato GGUF (K-Quants) reduce la precisión de los pesos de la red a números enteros de 4 o 5 bits mediante algoritmos de cuantización por bloques:

Tipo de Cuantización Bits / Peso VRAM Requerida (Modelo 8B) Pérdida de Perplejidad / Calidad Recomendación de Uso
FP16 / BF16 16.0 bits ~16.5 GB VRAM 0.00 % (Línea base) Solo para investigación en GPUs de 24 GB (RTX 4090 / A5000).
Q8_0 8.5 bits ~8.5 GB VRAM < 0.01 % (Prácticamente idéntica) Ideal para workstations con GPUs de 12 GB o 16 GB.
Q5_K_M 5.5 bits ~5.6 GB VRAM < 0.15 % (Excelente razonamiento) El balance óptimo calidad/memoria.
Q4_K_M 4.5 bits ~4.7 GB VRAM < 0.50 % (Inapreciable en uso general) El estándar recomendado: Corre en GPUs de 6 GB a 8 GB o en RAM.
Q2_K / IQ2 2.5 bits ~3.1 GB VRAM > 5.0 % (Degradación notable) Solo para dispositivos embebidos con muy poca RAM.

Instalación, comandos esenciales y catálogo de modelos

La instalación en Linux o macOS requiere un único comando en terminal:

curl -fsSL https://ollama.com/install.sh | sh

Modelos líderes recomendados en 2026:

  • ollama run llama3.1:8b — El modelo de propósito general más balanceado del mundo (Meta), con ventana de contexto de 128k tokens y excelente razonamiento en español.
  • ollama run qwen2.5-coder:7b — Especializado en desarrollo de software, generación de código en C++, Python y depuración de errores.
  • ollama run deepseek-r1:8b — Modelo de razonamiento profundo con cadena de pensamiento (Chain of Thought) abierta para problemas matemáticos y de ingeniería.
  • ollama run phi3.5:3.8b — Modelo ultra-compacto de Microsoft optimizado para laptops modestas y dispositivos Edge (Raspberry Pi 5 / Orange Pi 5).

Creación de agentes y modelos especializados con Modelfile

Al igual que Dockerfile permite crear contenedores personalizados, el Modelfile de Ollama permite congelar instrucciones del sistema (System Prompts), parámetros de temperatura y documentos de referencia dentro de un nuevo modelo ejecutable:

# Crear archivo "Modelfile":
FROM llama3.1:8b-instruct-q8_0

# Configurar hiperparámetros de inferencia
PARAMETER temperature 0.2
PARAMETER top_p 0.9
PARAMETER top_k 40
PARAMETER num_ctx 16384
PARAMETER stop "<|eot_id|>"

# Asignar personalidad y restricciones de ingeniería
SYSTEM \"\"\"
Eres un asistente de ingeniería robótica especializado en ROS 2, cinemática y control embebido.
Tus respuestas deben ser rigurosas, incluir código funcional bien comentado en C++17 o Python,
y respetar siempre las normativas de seguridad funcional industrial (ISO 13849-1).
\"\"\"

Para compilar y registrar el modelo localmente:

ollama create robotico-gpt -f ./Modelfile
ollama run robotico-gpt

API REST local e interfaz web con Open WebUI

Ollama expone un servidor HTTP local en el puerto 11434 totalmente compatible con el SDK oficial de OpenAI:

from openai import OpenAI

# Cliente apuntando al servidor Ollama local (¡Cero costos de API!)
client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama",  # Requerido por sintaxis pero ignorado
)

response = client.chat.completions.create(
    model="llama3.1:8b",
    messages=[
        {"role": "system", "content": "Eres un experto en electrónica."},
        {"role": "user", "content": "Explica la diferencia entre un MOSFET canal N y canal P."},
    ],
    temperature=0.3,
)

print(response.choices[0].message.content)

Interfaz gráfica con Open WebUI en Docker:

Para tener una experiencia idéntica a ChatGPT con soporte de carga de PDFs (RAG), gestión de usuarios y búsqueda web local:

docker run -d -p 3000:8080 --add-host=host.docker.internal:host-gateway \
  -v open-webui:/app/backend/data --name open-webui --restart always \
  ghcr.io/open-webui/open-webui:main

Preguntas Frecuentes

¿Qué hardware mínimo necesito para correr Llama 3.1 8B a buena velocidad?

El mínimo recomendado es una CPU de 6 núcleos con 16 GB de RAM del sistema (rendimiento de ~10-15 tokens/segundo). Con una GPU dedicada NVIDIA RTX 3060 de 12GB o una Mac con chip Apple Silicon M1/M2/M3 (16GB de memoria unificada), la velocidad salta a 60 a 90 tokens/segundo, superando con creces la velocidad de lectura humana.

¿Qué sucede si un modelo no cabe completamente en la VRAM de mi GPU?

Ollama y llama.cpp implementan offloading automático por capas (Layer Offloading): si tu GPU solo tiene 6 GB de VRAM y el modelo requiere 8 GB, cargará 22 capas en la GPU y las 10 capas restantes en la memoria RAM del sistema, funcionando sin crasheos.

¿Mis datos se envían a servidores de Ollama al usar este software?

No. Ollama corre 100% de forma local en tu máquina. La única comunicación externa ocurre cuando descargas un modelo nuevo desde la biblioteca pública (similar a un `docker pull`). Una vez descargado, puedes desconectar el cable de red y el modelo seguirá respondiendo con total normalidad.

¿Qué es la ventana de contexto (Context Window / num_ctx)?

Es la cantidad máxima de texto (tokens de conversación previa + documentos + respuesta) que el modelo puede recordar simultáneamente. Por defecto, Ollama utiliza 2.048 tokens; puedes aumentarlo hasta 32.768 o 128.000 tokens en el Modelfile mediante el parámetro `num_ctx 32768` (aumenta el consumo de memoria RAM/VRAM).

¿Puedo usar Ollama para hacer Function Calling (Llamadas a herramientas externas)?

Sí. Modelos modernos como Llama 3.1 y Qwen 2.5 soportan nativamente Function Calling y salida estructurada en formato JSON estricto mediante la API de Ollama, permitiendo que el LLM ejecute comandos de bash o interactúe con sensores de Arduino y PLC.
