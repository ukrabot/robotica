Qué hace un PLC en una célula robótica

El PLC (Controlador Lógico Programable) es el cerebro de planta: coordina el brazo robótico con el resto de la línea de producción. El controlador del robot se encarga de mover los ejes con precisión; el PLC decide cuándo debe hacerlo y en qué secuencia.

  • Secuenciación: ordena las etapas del proceso (transportador → robot → prensa → expulsión).
  • Control de periféricos: pinzas, sensores, válvulas, motores de transportadores, torretas y mesas posicionadoras.
  • Gestión de alarmas: centraliza fallas, estados y paradas de la línea.
  • Intercambio de datos: recibe y entrega información del robot por E/S discretas o por bus de campo.
  • Seguridad: mediante un PLC de seguridad, ejecuta paradas de emergencia, monitoreo de puertas y cortinas de luz.

En una arquitectura típica, el PLC actúa como maestro y el controlador del robot como esclavo de la secuencia: el PLC arranca el programa del robot, espera sus confirmaciones y decide el siguiente paso. Esta división de responsabilidades es la que hace escalable y mantenible una célula con varios robots y equipos.

IEC 61131-3: los cinco lenguajes

La norma IEC 61131-3 estandariza los lenguajes de programación de los PLC. Conocerlos te permite programar en cualquier marca y leer programas ajenos sin depender de un fabricante.

Los cinco lenguajes definidos por IEC 61131-3 y su uso típico en robótica.
LenguajeTipoUso típico
Ladder (LD)GráficoLógica de enclavamiento, E/S discretas, seguridad visible
Diagrama de Bloques (FBD)GráficoLógica combinacional, procesamiento de señales, lazos
Texto Estructurado (ST)TextualAritmética, bucles, manejo de datos y comunicaciones
Lista de Instrucciones (IL)TextualEn desuso; sustituido por ST en la mayoría de los entornos
Secuencial (SFC)GráficoMáquinas de estados: etapas, transiciones y ciclos

Para robótica, los tres más relevantes son LD, ST y SFC: LD para enclavamientos y lógica de campo, ST para cálculos y comunicación, y SFC cuando el proceso es una secuencia de etapas con transiciones claras (arranque, trabajo, fin de ciclo, falla).

Ladder (LD) vs Texto Estructurado (ST)

La decisión más frecuente al programar una célula es elegir entre escalera y texto estructurado. No es una competencia: son herramientas complementarias.

  • Ladder (LD): intuitivo para quien viene del cableado eléctrico; ideal para lógica de contactos, enclavamientos y seguridad. Se vuelve ilegible cuando hay cálculos, comparaciones múltiples o bucles.
  • Texto Estructurado (ST): parecido a Pascal; mucho más potente para aritmética, estructuras de datos y comunicación. Exige más disciplina para depurar, sobre todo en paradas de emergencia.
Regla práctica: deja en Ladder los enclavamientos y la lógica que un electricista deba leer rápido; usa ST en bloques de función que calculan, filtran o conversan con el robot.

Variables, temporizadores y bloques de función

Todo programa de PLC manipula variables. Las más comunes en una célula robótica son:

  • Entradas (I): sensores, finales de carrera, confirmaciones del robot.
  • Salidas (Q): actuadores, válvulas, arranques y comandos hacia el robot.
  • Marcas (M): banderas internas de estado (en ciclo, pieza lista, falla).
  • Bloques de datos (DB): estructuras para contadores, recetas y datos de comunicación.

Los temporizadores son indispensables. El TON (retardo a la conexión) filtra rebotes de sensores y confirma que una señal se mantiene estable; el TOF (retardo a la desconexión) mantiene una acción un instante tras quitar la condición; el TP genera un pulso de duración fija. En robótica se usan para validar que una pieza llegó, que una pinza cerró o que el robot respondió dentro del tiempo esperado.

El handshake PLC ↔ robot

El handshake es el protocolo de señales que sincroniza al PLC con el controlador del robot. Cada transición importante se acusa de recibo para que ninguno se adelante.

Señales típicas del handshake entre PLC y robot.
DirecciónSeñalSignificado
PLC → robotStart / StopArrancar o detener el programa del robot
PLC → robotSelección de programaQué rutina debe ejecutar el robot
PLC → robotPermiso de avanceEl periférico está listo para que el robot actúe
Robot → PLCEn posiciónEl robot llegó al punto objetivo
Robot → PLCCiclo terminadoEl robot finalizó su rutina y libera la zona
Robot → PLCEn falla / En automáticoEstado operativo del robot

La regla de oro es no actuar sin confirmación: el PLC solo abre la pinza o avanza el transportador cuando el robot confirma que terminó. Saltarse este acuse es la causa más común de colisiones y piezas dañadas en celdas nuevas.

Ejemplo: pick & place paso a paso

Escenario: el robot toma una pieza de un transportador y la deposita en una matriz. La secuencia la controla el PLC en texto estructurado, con temporizadores para validar cada confirmación.

// Pick & place — texto estructurado (IEC 61131-3)
// Etapa 0: esperar la orden de inicio del operador
IF boton_inicio AND NOT en_ciclo THEN
    en_ciclo := TRUE;
    orden_start := TRUE;        // arranca el programa del robot
END_IF;

// Etapa 1: el robot confirmó que llegó a la zona de recogida
IF en_ciclo AND robot_en_punto THEN
    cerrar_pinza := TRUE;       // la pinza sujeta la pieza
END_IF;

// Etapa 2: la pinza confirmó cierre (sensor) tras 200 ms estables
t_confirmacion(IN := pinza_cerrada, PT := T#200ms);
IF en_ciclo AND t_confirmacion.Q THEN
    orden_depositar := TRUE;    // el robot puede ir a la matriz
END_IF;

// Etapa 3: fin de ciclo confirmado por el robot
IF en_ciclo AND robot_ciclo_terminado THEN
    en_ciclo := FALSE;
    orden_start := FALSE;
    contador := contador + 1;
END_IF;

Observa el patrón: cada etapa avanza solo cuando llega la confirmación de la etapa anterior. El temporizador t_confirmacion evita que un rebote del sensor de la pinza dispare una transición falsa. Este mismo esqueleto se reutiliza en casi cualquier secuencia industrial.

El PLC de seguridad

Las funciones de seguridad no se programan en el PLC estándar: se ejecutan en un PLC de seguridad con entradas de doble canal, vigilancia cruzada y certificación hasta PL e (ISO 13849-1) o SIL 3 (IEC 62061).

  • Parada de emergencia: circuitos redundantes que quitan la energía del movimiento.
  • Puertas y cortinas: monitoreo de accesos con enclavamiento y rearme manual.
  • Velocidad segura: límite de velocidad monitoreado en operación colaborativa o de ajuste.
  • Bus de seguridad: PROFIsafe, FSoE o CIP Safety integran estas señales en la misma red que el proceso.

El diseño de estas funciones se detalla en las guías de Parada de Emergencia e Integración de Cortinas de Luz. Un PLC de seguridad bien configurado es una capa de protección, no un reemplazo de la evaluación de riesgos de la célula.

Conclusión

Programar un PLC para robótica es coordinar, no mover: el PLC organiza la secuencia, valida cada confirmación y resguarda la seguridad. Dominar IEC 61131-3 (con Ladder para lo visible y ST para lo complejo) y respetar el handshake con el robot son las dos habilidades que separan una célula que arranca a la primera de una que persigue fallas durante semanas.
