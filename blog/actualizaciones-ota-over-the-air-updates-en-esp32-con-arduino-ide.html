Actualizaciones OTA (Over-the-Air) en ESP32 con Arduino IDE

Cuando el dispositivo ya está instalado en el techo o dentro de una caja sellada, subir firmware por USB deja de ser opción. Esta guía cubre los tres métodos OTA del ecosistema Arduino-ESP32, el esquema de particiones que los hace posibles y cómo no convertir tu actualización en un ladrillo remoto.

Cómo funciona OTA por dentro: particiones y otadata

El ESP32 no sobreescribe el firmware que está ejecutando. La flash de 4 MB se divide en particiones de aplicación —típicamente ota_0 y ota_1 de ~1,5 MB cada una— más una pequeña partición otadata que registra cuál es la válida. El flujo es:

  1. El firmware activo en ota_0 recibe el binario nuevo y lo escribe en ota_1.
  2. Al terminar, marca otadata apuntando a ota_1 y reinicia.
  3. El bootloader lee otadata y arranca la partición nueva.

Si la escritura se interrumpe (corte de energía, Wi-Fi caído), la partición antigua sigue intacta y el dispositivo sigue arrancando con ella: el OTA es atómico por partición. El riesgo real no es el corte a mitad de descarga sino un firmware nuevo que no funciona y se reinicia en bucle —para eso existe el rollback (ver seguridad).

Consecuencia práctica: con OTA activo tu sketch dispone de ~1,5 MB, no de los ~3 MB de un esquema sin OTA. Bibliotecas pesadas (WebSocket, TLS, interfaces web embebidas) pueden no caber: verifica el tamaño compilado antes de diseñar el producto.

Método 1: ArduinoOTA desde el IDE

Es el método de desarrollo: el IDE descubre el ESP32 por mDNS en la red y le envía el binario al compilar, igual que un puerto serie.

#include <WiFi.h>
#include <ArduinoOTA.h>

const char* ssid = "mi_red";
const char* pass = "mi_clave";

void setup() {
  Serial.begin(115200);
  WiFi.mode(WIFI_STA);
  WiFi.begin(ssid, pass);
  while (WiFi.waitForConnectResult() != WL_CONNECTED) {
    Serial.println("Fallo WiFi; reinicio en 5 s");
    delay(5000); ESP.restart();
  }

  ArduinoOTA.setHostname("sensor-techo");
  ArduinoOTA.setPassword("clave-ota-8-caracteres");

  ArduinoOTA.onStart([]() { Serial.println("Inicio OTA"); });
  ArduinoOTA.onEnd([]() { Serial.println("\nFin OTA"); });
  ArduinoOTA.onProgress([](u32_t p, u32_t t) {
    Serial.printf("Progreso: %u%%\r", (p / (t / 100)));
  });
  ArduinoOTA.onError([](ota_error_t e) {
    Serial.printf("Error[%u]\n", e); ESP.restart();
  });
  ArduinoOTA.begin();
}

void loop() { ArduinoOTA.handle(); }

Después de cargar este sketch por USB una sola vez, el puerto "Red" aparece en el menú de placas del IDE (la primera vez, instala el soporte mDNS: Bonjour en Windows, Avahi en Linux). Regla de oro: todo sketch posterior debe incluir este mismo código OTA, o perderás el acceso remoto en la siguiente subida.

Método 2: Web Updater con formulario

El ESP32 sirve una página donde subes el archivo .bin desde el navegador. No requiere mDNS ni IDE: útil para instalaciones en redes ajenas o para que un técnico actualice sin toolchain.

#include <WiFi.h>
#include <WebServer.h>
#include <ESPmDNS.h>
#include <Update.h>

WebServer server(80);

const char* pagina =
  "<form method='POST' action='/update' enctype='multipart/form-data'>"
  "<input type='file' name='update'><input type='submit' value='Actualizar'></form>";

void subir() {
  server.sendHeader("Connection", "close");
  server.send(200, "text/html", pagina);
}

void actualizar() {
  HTTPUpload& upload = server.upload();
  if (upload.status == UPLOAD_FILE_START) {
    uint32_t maxSketch = ESP.getFreeSketchSpace() - 0x1000;
    if (!Update.begin(maxSketch, U_FLASH)) Update.printError(Serial);
  } else if (upload.status == UPLOAD_FILE_WRITE) {
    if (Update.write(upload.buf, upload.currentSize) != upload.currentSize)
      Update.printError(Serial);
  } else if (upload.status == UPLOAD_FILE_END) {
    if (Update.end(true)) {
      server.send(200, "text/plain", "OK. Reiniciando...");
      delay(500); ESP.restart();
    } else Update.printError(Serial);
  }
}

void setup() {
  WiFi.begin("mi_red", "mi_clave");
  while (WiFi.status() != WL_CONNECTED) delay(200);
  MDNS.begin("sensor-techo");
  server.on("/", HTTP_GET, subir);
  server.on("/update", HTTP_POST, [](){}, actualizar);
  server.begin();
}
void loop() { server.handleClient(); }

El binario se genera con Sketch → Exportar binario compilado. Protege la página: al menos autenticación básica HTTP y credenciales Wi-Fi propias, porque cualquiera en la red podría flashear el dispositivo.

Método 3: actualización desde servidor HTTP(S)

Para flotas, el dispositivo consulta un servidor y se actualiza solo. La clase ESP32HTTPUpdate hace todo el trabajo:

#include <ESP32httpUpdate.h>

void actualizarDesdeServidor() {
  WiFiClientSecure client;
  client.setInsecure();            // producción: usar CA real
  t_httpUpdate_return ret = ESP32HTTPUpdate::update(
      client, "https://firmware.midominio.cl/v2/sensor.bin");

  switch (ret) {
    case HTTP_UPDATE_FAILED:
      Serial.printf("Error [%d]: %s\n",
        ESP32httpUpdate.getLastError(),
        ESP32httpUpdate.getLastErrorString().c_str());
      break;
    case HTTP_UPDATE_NO_UPDATES: Serial.println("Sin novedades"); break;
    case HTTP_UPDATE_OK: Serial.println("Actualizado"); break;
  }
}

Puedes añadir cabecera de versión (ESP32HTTPUpdate::setHeader("x-esp32-version", fw_version)) y que el servidor devuelva 304 si no hay novedad. Combínalo con un registro de versión persistente en Preferences y una política de reintento con backoff para no saturar el servidor si algo falla.

Elegir el esquema de particiones correcto

En Herramientas → Partition Scheme elige uno con dos particiones OTA. Los habituales en flash de 4 MB:

EsquemaApp (cada OTA)SPIFFSUso
No OTA (1APP)~3,1 MB~1,9 MBSin actualización remota
OTA estándar~1,3 MB~1,4 MBBalance general
Minimal SPIFFS + OTA~1,9 MB~64 KBSketch grande con OTA

Cuando el proyecto crece (TLS + interfaz web + lógica), el esquema "Minimal SPIFFS" es el que salva. Y si el binario no cabe en ninguna partición OTA, la solución correcta es pasar a un módulo con flash de 8 o 16 MB, no desactivar OTA.

Seguridad: HTTPS, firmas y contraseñas

  • Nunca OTA plano en producción: usa HTTPS con verificación de CA (guarda el certificado en el firmware) o, mejor, binarios firmados: con ESP-IDF se habilita Secure Boot v2 y la verificación de firma de imagen, de modo que el bootloader rechaza binarios sin firmar aunque un atacante controle el canal.
  • ArduinoOTA es para desarrollo: su contraseña viaja en el handshake y el protocolo no está pensado para redes hostiles. En producción, apágalo tras el despliegue.
  • Rollback: habilita el modo rollback (CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE en el SDK; en Arduino, marcando la app como válida con esp_mark_app_valid o confiar en el comportamiento tras el primer boot) para que un firmware que no confirma su arranque revierta a la partición anterior automáticamente.
  • Versionado e idempotencia: envía la versión en el binario y en el servidor; un dispositivo actualizado no debe re-descargar el mismo archivo.

Buenas prácticas y recuperación de fallos

  1. Nunca borres el código OTA de sketches futuros: es la forma más común de perder acceso remoto.
  2. Prueba el binario en un gemelo (mismo modelo, mismo esquema de particiones) antes de la flota.
  3. Actualiza por ventanas: en dispositivos a batería, haz OTA solo con batería sana o fuente estable; un corte en el arranque inicial del firmware nuevo es el peor momento.
  4. Guarda telemetría pre/post: versión, motivo de reinicio (esp_reset_reason()) y resultado del Update para detectar regresiones a distancia.
  5. Plan B físico: deja accesible el puerto USB o un botón que fuerce modo AP + web updater; el OTA reduce viajes, no los elimina.

Con estos tres métodos cubres el ciclo completo: ArduinoOTA para iterar en el banco, web updater para instalaciones puntuales y servidor HTTP(S) con rollback para operar una flota con seriedad.

Preguntas frecuentes

¿Pierdo el sketch actual si se corta la luz durante una actualización OTA?

No. El firmware nuevo se escribe en la partición alternativa; si se interrumpe, otadata sigue apuntando a la partición antigua y el dispositivo arranca con ella.

¿Por qué mi sketch con OTA compila más grande de lo que cabe?

El esquema con OTA divide la flash en dos particiones de aplicación (~1,3–1,9 MB cada una). Usa el esquema "Minimal SPIFFS (Large APPS with OTA)" o un módulo con más flash.

¿Es seguro usar ArduinoOTA en producción?

No: fue diseñado para desarrollo. En producción usa HTTPS con verificación de certificado o binarios firmados con Secure Boot v2, y desactiva ArduinoOTA.

¿Qué es el rollback de OTA y cuándo lo necesito?

Es el mecanismo que revierte automáticamente a la partición anterior si el firmware nuevo no confirma su primer arranque. Es esencial en flotas remotas donde nadie puede presionar RST.
